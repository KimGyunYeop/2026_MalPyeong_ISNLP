[근거 생성시 지켜야할 것]
각 rationale은 다음을 동시에 만족해야 한다.
- domain_match: 해당 영역의 기준만 사용하고 다른 영역의 결함을 섞지 않는다.
- score_rationale_consistency: 근거의 긍정·부정 강도가 고정 점수와 맞는다.
- specificity: 실제 주장, 이유, 전개 순서, 담화 표지, 문장 또는 표현 가운데 확인 가능한 특정 요소를 짚는다.
- groundedness: essay_text에 존재하는 내용만 말하며 없는 사례·통계·표현·오류를 만들지 않는다.

[세부 준거]
- content는 문제 상황 제시, 주장의 논제 부합성과 일관성, 주장과 이유·근거의 추론 연결, 이유·근거의 수와 전개 깊이, 실제로 다룬 다른 입장과 그 논박 수준을 본다.
- organization은 글 전체의 기능적 전개와 배열, 각 의미 단위의 완결성·통일성·문장 간 일관성을 본다.
- expression은 문장과 어휘의 자연성·명료성·효과성, 맞춤법·띄어쓰기·문법·오탈자·종결 방식과 글쓰기 관습을 본다.
- 아홉 준거를 기계적으로 나열하지 말고, 고정 점수를 가장 잘 설명하는 결정적 강점과 약점만 고른다. 다른 입장 부재나 통계·사례 부재를 모든 글의 상투적 약점으로 쓰지 마라.

[점수 강도 앵커]
- 5점: 본문에서 확인되는 매우 뚜렷하고 구체적인 강점을 중심으로 쓴다. 근거 없는 약점을 억지로 덧붙이지 않는다.
- 4점: 분명한 강점을 구체화하고, 점수를 제한하는 실제의 경미한 약점이 있으면 함께 짚는다.
- 3점: 실제 장점과 실제 약점을 함께 제시하여 부분 충족과 보통 수준을 드러낸다.
- 2점: 기준 충족을 제한하는 주요 결함을 구체적으로 짚고, 확인되는 제한적 성취만 덧붙인다.
- 1점: 기준을 거의 충족하지 못하게 하는 심각한 결함 또는 핵심 요소의 부재를 본문에 비추어 명확히 설명한다.
- 고정 점수의 숫자 표기를 그대로 따른다. 소수 점수라면 양옆 정수 앵커 사이의 강도로 표현하되, 반올림하거나 표기를 바꾸지 않는다.

[영역별 evidence atom]
- content: 글의 실제 입장과 실제 이유·근거를 이름 붙여 말하고, 둘의 연결 또는 전개 깊이가 점수를 어떻게 뒷받침하는지 설명한다. 단순히 ‘근거가 부족하다’고 하지 말고, 무엇을 이유로 들었으며 어느 연결이나 설명이 충분히 전개되지 않았는지를 밝힌다.
- organization: 제공된 essay_text는 원래의 줄바꿈과 형식 문단 경계가 보존되지 않은 평면 문자열이다. 줄바꿈 부재, 문단 수, 문단 구분, ‘문단 간 전환’을 근거로 삼지 마라. 대신 앞부분의 문제 제기·입장, 이어지는 이유들의 순서, 반론·대안, 마무리의 기능적 연결을 짚고, ‘첫째’, ‘그러나’, ‘따라서’ 같은 표지는 실제 문자열에 있을 때만 언급한다.
- expression: 자연스럽거나 어색한 실제 문장·어휘·오류 양상을 짚는다. 오류를 인용할 때는 틀린 형태를 고쳐 쓰지 말고 essay_text의 짧은 문자열을 그대로 옮긴다. 내용의 사실성이나 논거의 타당성을 표현 문제로 평가하지 않는다. 높은 점수에서도 ‘오류가 없다’라는 총평만 쓰지 말고 실제 어휘나 문장 표현을 근거로 든다.

[근거 작성 규칙]
- 영역별 rationale은 한국어 두 문장 이내이며 공백을 포함해 각각 180자 이내이다.
- 각 rationale에는 최소 한 개의 검증 가능한 evidence atom을 포함한다. 한 문장은 구체적 관찰, 다른 한 문장은 그 관찰과 고정 점수의 강도를 연결하는 방식이 좋다.
- ‘명확하다’, ‘자연스럽다’, ‘논리적이다’, ‘부족하다’ 같은 총평만 단독으로 쓰지 마라.
- 부재를 말할 때는 글 전체를 확인하고, 실제로 제시된 요소와 대비하여 무엇이 끝내 제시·전개되지 않았는지 밝힌다.
- 직접 인용은 선택 사항이다. 인용한다면 작은따옴표를 사용하고, essay_text에 연속된 부분 문자열로 정확히 존재해야 한다. 고쳐 쓴 인용, 의역, 줄임표로 이어 붙인 인용, 조사·어미를 떼어 낸 인용은 금지한다.
- 외부 지식으로 사실 여부를 판정하지 말고, prompt_text의 정보를 essay_text가 직접 쓴 내용인 것처럼 말하지 마라.
- 세 영역은 서로 다른 증거를 사용하고 상투적인 문장을 반복하지 마라. 준거 코드나 내부 점검 과정은 출력하지 마라.

[출력 규칙]
- 아래 스켈레톤과 같은 JSON 객체 하나만 출력한다. 설명, 코드 블록, 마크다운, 앞뒤 문장을 붙이지 마라.
- content, organization, expression을 모두 포함하고 키를 추가·삭제하지 마라.
- score는 스켈레톤의 숫자를 그대로 유지하고 rationale 문자열만 교체한다.
- `<content 근거, ...>` 같은 꺾쇠 안 문구는 설명용 자리표시자이다. 그대로 복사하지 말고 essay_text에 근거한 실제 rationale로 완전히 교체한다.
- JSON 문자열 내부에 큰따옴표를 쓸 때는 반드시 이스케이프해야 한다. 인용이 필요하면 작은따옴표를 우선 사용한다.
